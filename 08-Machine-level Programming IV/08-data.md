## Access
![[Pasted image 20260524112006.png|615]]
指针就是存储地址一段内存，指针和数组是**等价**的（但是需要注意的一点是——数组名这个指针**始终指向数组的第一个元素，无法更改**）
所以对于不同数据类型的数组，其指针自增所增加的量**不同**（和数据类型有关）
比如`char *pc`和`int *pi`
```
pc++ <=> pc指向的地址加1
pi++ <=> pi指向的地址加4
```
同时，C语言数组的语法糖
```
val[x] <=> *(x + val) <=> &val + x * sizeof(val[0])处的元素
```
这也表面**允许负数索引**，但和Python中的循环不同，C语言是**直接访问数组以外的区域**

# Structures
## 简介
对C语言结构体很熟的可以跳过，这里用作复习
C语言的结构体和Java的类比较相似，比如下面的对于矩形的定义：
```C
struct rect {
    long x;
    long y;
    unsigned long w;
    unsigned long h;
    unsigned color;
};
```
我们便可以申明一个`struct rect`类型的变量
```C
struct rect r;
r.x = r.y = 0;
r.w = 10;
r.h = 20;
r.color = 0xFF00FF;
```
或者也可以
```C
struct rect r = {0, 0, 10, 20, 0xFF00FF}; //保证一一对应
```
通常（几乎）我们都使用指针来传递结构体（这么做是由于C语言是[[L3 Reference Recursion intList#^342a3d|值传递]]的）
```C
long area(struct rect *rp) {
    return (*rp).w * (*rp).h;
}
```
由于过于常用，C有一个简化写法`rp->w`

### Alignment Principles
大多数机器一次取**64字节**。一般来说，如果没有一个**对齐的地址**，一个特定的数据跨过两个块时，会让硬件或者操作系统来采取额外步骤来处理（对于x86来说会导致效率变低，而对于某些机器甚至会导致错误）

### Specific Cases of Alignment(x86-64)
如果一个地址是$2^k$的倍数，他的低k位一定全为0
![[Pasted image 20260526110600.png|476]]
以short(2 Byte)举例
```
地址
0x1000 可以放   -> 0x0 = 0000
0x1001 不可以放 -> 0x1 = 0001
0x1002 可以放   -> 0x2 = 0010
0x1003 不可以放 -> 0x3 = 0011
```
很好理解，实际上就是要求k字节的数据的起始地址要为k的倍数，而k(二的幂)的二进制表示的低log k位为0。

结构体的**起始地址必须是K的倍数**（**在结构体中**，K代表其中所有成员的最大对齐要求），同时，结构体大小**必须是K的倍数**：

# Floating Point
使用`%xmm`寄存器`%xmm0,xmm1,......`，返回值放在`%xmm0`中，此外还有`%ymm`寄存器`%ymm0,ymm1,......`
注意，上面所述的寄存器可以存放整数也可以存放浮点数，他们本身没有类别，只是存储位——类型是解释的问题。
## 浮点传送
引用内存的指令是**标量**指令，意味着它们只对单个而不是一组**封装好的数据值**进行操作
- 标量：只存单个数
- 封装数据：一个寄存器里存“多个数”（名义上）——SIMD
![[Pasted image 20260616081837.png|655]]
- 对于XMM寄存器到XMM寄存器：使用**传送双精度和单精度的指令都是一样的**（结果或者效率是一样的）
- 对齐：指令名字中的`a`是“对齐”的意思，当用于读写内存时，如果地址**不满足16字节对齐，会导致异常**——但是在**两个寄存器之间**传送数据一定不会出现错误对齐
## 浮点转换
把浮点数转换为整数时，指令会执行截断，把值向0进行舍入。
![[Pasted image 20260616083522.png]]
如果想要把一个整数转换为单精度浮点——`vcvtsi2sdq %rax, %xmm1, %xmm1`
这里`%rax`只会改变`%xmm1`的低字节，而 *源2* 会改变`%xmm1`的高位（**就是复制过来低位的更高位**——所以恰好不改变低位数据）

虽然使用`vcvtss2sd %xmm0, %xmm0, %xmm0`就能实现单精度向双精度的转换了，但是实际上GCC会产生如下代码：
```s
vunpcklps %xmm0, %xmm0, %xmm0 
vcvtps2pd %xmm0, %xmm0
```
`vunpcklps`交叉放置来自两个XMM寄存器的值，也就是`[s3,s2,s1,s0], [d3,d2,d1,d0]——>[s1,d1,s0,d0]`
对于上面GCC的奇妙代码，原始寄存器的值为`[s3,s2,s1,s0]`，那么第一个指令将其更新为`[s1,s1,s0,s0]`，而第二个指令把寄存器中的**两个低位单精度值扩展为目的XMM寄存器中的两个双精度值**`[ds0,ds0]`（取源寄存器的低 64 位，然后把他们**都变为双精度**，放到目标寄存器中）
### Example
```s
vcvtsi2sdq  %rcx, %xmm1, %xmm1
vmovsd      %xmm1, (%rdx)
```
`%rcx`里存放long类型数据
```
%rcx  = 0x0000000000000003
%xmm1 = [ 0xAAAAAAAAAAAAAAAA | 0xBBBBBBBBBBBBBBBB ]  
	                    高64位 低64位
```
第一条指令先把rcx的位表示变为double类型：
```
0x0000000000000003 -> 0x4008000000000000
```
然后低位为`%rcx`，高位保持不变
```
%rcx  = 0x4008000000000000
%xmm1 = [ 0xAAAAAAAAAAAAAAAA | 0x4008000000000000 ]  
	                    高64位 低64位
```
`vmovsd` 这里是把 `%xmm1` 的低 64 位存到内存
