## Code Injection Attacks
![[Pasted image 20260608102602.png|559]]
利用缓冲区溢出，我们可以精确地修改返回地址，使得这个地址就是我们想要让被攻击者执行的代码。比如，本来在Q函数ret的时候，程序应该回到调用Q的下一句，但是实际上这个地址被黑客修改为了窃取信息的**程序**。
## Solution
### 安全的函数：
使用`fgets(buf, 4, stdin)`，它会截断超过4个字符的字符串；`scanf`的格式字符串不用`%s`而是`%ns`以指定最大输入的字符串长度
### 栈随机化(ASLR)
地址空间布局随机化：每次程序运行的时候，其地址是变化的。堆和栈都是随机的
![[Pasted image 20260608203223.png|400]]
具体的实现是：在每次程序开始的时候，在栈上分配一段`0~n`字节之间的随机大小的空间。程序不使用这段空间，但是他会**导致程序每次执行以后的栈位置发生变化**
但是，随机化可以通过暴力枚举，遍历每一种情况(nop sled)，从而被破解
### 限制可执行代码区
就算在栈里面加入一段恶意代码，并且通过修改地址使得CPU执行的语句跳转到该位置，由于现代系统通常把**栈标记为不可执行**，这一段注入代码依旧不被执行

## Return-Oriented Programming Attacks
全局变量和代码本身的位置没有变，如果我们找到代码的位置，我们可以在那段代码里面注入我们的恶意代码。
gadget：部分可执行程序的字节系列，最后的字节是0xc3（对应`ret`）
### Example
比如有些函数实现了一些对攻击者来说非常有用的操作，甚至不一定是主动实现的，而是碰巧出现的。我们只用机器内部的碎片代码(gadget)，拼凑（使用`0xc3`也就是`retq`）出我们想要注入的完整代码：
![[Pasted image 20260609150354.png]]
虽然这个代码只是一个赋值的，但是他的二进制码中恰好出现了`48 89 c7`这对应`movq %rax, %rdi`，这个命令的字节起始的`48`的地址为`0x4004d9+3=0x4004dc`
### ROP Execution
![[Pasted image 20260609152221.png]]
黑客把Stack**充满了Gadget的地址**，当某个函数执行到`ret`命令的时候，**从栈顶弹出一个地址，作为接下来要执行的语句的地址**（这里就是Gadget 1的地址），然后不断进行下去，知道把整段恶意代码执行完毕

# 补充
## 小端序
低地址存低有效字节，地址越高，字节越高位。
比如一个32位整数：`0x0A0B0C0D`，在内存里要按照低地址到高地址存为：`0D 0C 0B 0A`
